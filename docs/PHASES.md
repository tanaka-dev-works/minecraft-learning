# 開発フェーズ計画

制作プロンプト v4 と技術スタック整理（素の HTML / CSS / JS、ビルドなし、GitHub Pages）をもとに、作業を **1フェーズ＝1セッション＝1PR** に分けています。
各フェーズには「完了の条件」をつけ、条件を満たしたら PR をマージして次へ進みます。

## 進み具合（2026-11-03）

- フェーズ1〜8：完了（基本編ができあがり）。完成条件のチェックは [CHECK.md](CHECK.md)、未確認の項目は [UNVERIFIED.md](UNVERIFIED.md)
- おためし・フェーズ9：息子さんの結果待ち（結果が来るまでは先にフェーズ10・11を進める）
- フェーズ10・11：完了（応用編：コマンド大ずかん、応用の作品3つ）

## 進め方のきまり

- 1フェーズでやることは表の範囲だけにします。はみ出しそうなら次のフェーズに回し、この表を書き直します。
- 実機でしか分からないことは【要実機確認】と書き、`docs/DESIGN.md` の「確認したい点」にためていきます。
- 各 PR には「完了の条件」のチェック結果と、タブレット幅のスクリーンショット確認の結果を書きます。
- 自動チェックは `node tests/check.mjs` で動きます（Playwright を使用）。
