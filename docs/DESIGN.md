# 設計書（フェーズ1）

制作プロンプト v4 の「フェーズ1：設計」にあたる文書です。ここで決めたことをもとに、フェーズ2以降でページを作ります。
変えたいところがあれば、この文書を直してから次のフェーズに進みます。

## 1. 子どもの道すじ

トップは「レベルのすごろく」だけを大きく見せます。子どもはすごろくの「つぎは ここ！」を押して進むだけで、迷わないようにします。

```
トップ（すごろく）
  └ レベル1 → レベル2 → … → レベル6      ← 子どもの道すじ（一本道）
       各レベル：やってみる → 何が起きた？ → なぜ？ → 作品 → 「できた！」でスタンプ → クイズ3問

「しらべる」（道すじの外。必要なときに開く）
  ├ コマンドずかん（基本編）／コマンド大図鑑（応用編）
  ├ コマンドの書き方／ばしょとあいて／コマンドブロック図鑑
  ├ トラブルかいけつ／エラーずかん
  ├ プログラミングってなに？（まとめ）
  ├ はやみひょう（2まい）
  └ やってはいけないコマンド

「おうちの人へ」（保護者だけ。外部リンクはここにだけ置く）
  ├ はじめに（ワールドの準備・チート・コマンドブロックの入手）
  ├ 安全の設定（みまもり設定、Microsoft アカウント）
  ├ レベルごとのつまずき・声かけ・時間
  └ 実機チェックリスト
```

## 3. レベルと作品

| レベル | テーマ | できるようになること | 作品 | 使うコマンド |
|---|---|---|---|---|
| 1 | コマンドを うって みよう | チャットでコマンドを打って動かせる。英数モードと記号の出し方が分かる | ① あさに なあれ／はれに なあれ | `/time` `/weather` `/say` |
| 2 | ばしょと あいてを きめよう | `~` と `@s` `@p` が使える | ② ブロック マジック（目の前にブロックを置く） | `/setblock` `/give` `/tp` `/summon` |
| 3 | コマンドブロックを うごかそう | コマンドブロックをボタンで動かせる | ③ ボタンで ダイヤモンド ④ メッセージ そうち | `/give` `/title` `/playsound` |
| 4 | めいれいを つなげよう | チェーンで「じゅんばんに」動かせる | ⑤ テレポート そうち ⑥ アイテム くばり そうち | `/tp` `/title` `/playsound` `/give` `/effect` |
| 5 | ずっと 見はらせよう | リピートと条件付きで「もし〜なら」ができる | ⑦ ちかづくと ひらく ドア | `/testfor`（または `/execute if`）、`/fill`、`/setblock` |
| 6 | じぶんの ゲームを つくろう | スコアで点数を数えられる | ⑧ かんたん ミニゲーム（まとあて／コインあつめ） | `/scoreboard` `/tag` `/execute` `/title` |

各レベルに「できるようになること」「チャレンジ（作品）」「たしかめクイズ3問」をつけます。
プログラミングの考え方（命令・順番・もし〜なら・くりかえし・まちがいさがし）は、各レベルの「なぜ そうなるの？」に分けて入れます（レベル1＝命令、2＝ひきすう、3＝きっかけ、4＝順番、5＝もし〜なら・くりかえし、6＝へんすう〔スコア〕、全体＝デバッグ）。

### 基本編に入れないもの

| コマンド | 理由 |
|---|---|
| `/clone` | 範囲を2回指定するので小2には長い。応用の作品（自動建築）で扱う |
| `/setworldspawn` | ワールド全体の復活場所が変わるので影響が大きい。`/spawnpoint` で足りる。応用編で扱う |

## 5. データの形（`js/data.js`）

`fetch` を使わず、`window.SITE_DATA` に全部をまとめます（`file://` でも動くように）。

```js
window.SITE_DATA = {
  levels: [ { id: 1, title: "コマンドを うって みよう", page: "pages/level1.html", ready: false } ],
  commands: [
    {
      id: "tp", name: "/tp", yomi: ["てれぽーと", "いどう", "tp", "teleport"],
      level: 2, edition: "switch",          // switch | bds | edu（応用編の3分類）
      kids: { what: "…", how: "…", args: [ … ], examples: [ "/tp @s ~ ~5 ~" ], careful: "…" },
      parents: { syntax: "…", permission: "…", note: "…", url: "https://learn.microsoft.com/…" },
      status: "doc",                        // doc（公式ドキュメントで確認済）| device（実機で確認済）| unknown（未確認）
      checkedVersion: null,
      related: ["setblock", "spawnpoint"]
    }
  ],
  works: [ … ], quizzes: [ … ]
};
```

保存（localStorage）は1つのキー `mcl-progress-v1` に JSON でまとめ、読み書きは必ず try/catch で囲みます。

```js
{ stamps: { "1": "2026-11-03" }, learned: ["tp"], favorites: [], steps: { "works/teleport": 3 } }
```

## 6. 見た目のきまり

- 色・余白・文字サイズは `css/style.css` の `:root` 変数にまとめる。色は草・土・石・空・ダイヤの5系統。
- 本文 20px 以上、コマンドの例文 28px 以上の等幅。ボタンは 60px 四方以上。
- ドット感は見出し・ボタン・カードの角だけ。本文は UD フォント。
- フォントはフェーズ2で同梱するまで、端末にある日本語フォント（Android なら Noto Sans CJK）を使う。
- 動きは少しだけ。`prefers-reduced-motion` で止める。
- フッターに「Mojang・Microsoft とは関係のない非公式の資料です」を全ページで出す。

## 7. 確認したい点（保護者の方へ）

### 先に決めてほしいこと
1. **サイトの名前**：仮に「マイクラ コマンド ぼうけん」にしています。
2. **案内キャラの見た目と名前**（フェーズ2で作ります）：例）ブロックのロボット、ネコ、オリジナルの小さな生き物 など。息子さんに選んでもらうのもおすすめです。
3. **GitHub Pages の公開**：無料プランで Pages を使うには、リポジトリを **Public（公開）** にする必要があります。公開してよいか確認させてください。

### 実機で確かめてほしいこと【要実機確認】
4. 携帯モードで、マイクラの画面キーボードを指で直接タップできるか。
5. チャット欄でコマンド候補が出たとき、それを選んで入力を省けるか。前に打ったコマンドを呼び出せるか（上ボタンなど）。
6. ワールドの「コピー」の手順（設定 → ワールドのコピー など、画面の名前）。
7. タイトル画面に出るバージョン番号（実機チェックリストに記入）。
8. タブレットの Chrome で「よみあげ」ボタンを押したとき、日本語の声で読まれるか（トップページで試せます）。
